# Git 신규 프로젝트 환경설정 가이드

> React + Vite + TailwindCSS + PWA 스택으로 새 프로젝트를 처음부터 만들어 GitHub Pages에 배포하는 범용 가이드.

---

## 시작 전 — 변수 정의

`{중괄호}` 로 표시된 부분을 본인 프로젝트에 맞게 바꿔서 사용한다.

| 변수 | 설명 | 예시 |
|------|------|------|
| `{프로젝트명}` | GitHub 저장소 이름 (대소문자 구분) | `irishPlay` |
| `{배포계정}` | GitHub Pages + Actions 실행 계정 | `mykim711231` |
| `{백업계정}` | 코드 미러/백업용 계정 | `gababayo` |
| `{로컬경로}` | 로컬 저장 폴더 경로 | `D:\_Git\irishPlay` |
| `{앱설명}` | 앱 한 줄 설명 | `아일랜드 학습 앱` |
| `{테마색상}` | PWA 테마 색상 (hex) | `#16a34a` |

## Remote 구성 구조

```
로컬 작업
    │
    ├── git push mykim main   →  {배포계정}/{프로젝트명}     (예: mykim711231/irishPlay)
    │                               └── GitHub Actions 자동 실행
    │                                       └── GitHub Pages 배포
    │                                               └── https://{배포계정}.github.io/{프로젝트명}/
    │                                               (예: https://mykim711231.github.io/irishPlay/)
    │
    └── git push origin main  →  {백업계정}/{프로젝트명}     (예: gababayo/irishPlay)
```

| remote 이름 | 연결 계정 | 역할 |
|-------------|----------|------|
| `mykim` | `{배포계정}` (예: `mykim711231`) | 배포 트리거 — push 시 Actions 실행 |
| `origin` | `{백업계정}` (예: `gababayo`) | 백업 — 코드 동기화 보관 |

> ⚠️ **remote 이름과 계정이 뒤바뀌지 않도록 주의한다.**  
> `origin`이 `{배포계정}`을 가리키면 push 시 권한 오류가 발생한다.

## 2단계 — 로컬 Git 초기화

```powershell
# 예: mkdir "D:\_Git\irishPlay"
mkdir "{로컬경로}"
cd "{로컬경로}"

git init
git branch -M main

# ⚠️ 순서 중요: mykim(배포) 먼저, origin(백업) 나중
# 예: git remote add mykim  https://mykim711231@github.com/mykim711231/irishPlay.git
# 예: git remote add origin https://github.com/gababayo/irishPlay.git
git remote add mykim  https://{배포계정}@github.com/{배포계정}/{프로젝트명}.git
git remote add origin https://github.com/{백업계정}/{프로젝트명}.git

git remote -v
```

정상 출력 (예):
```
mykim   https://mykim711231@github.com/mykim711231/irishPlay.git (fetch)
mykim   https://mykim711231@github.com/mykim711231/irishPlay.git (push)
origin  https://github.com/gababayo/irishPlay.git (fetch)
origin  https://github.com/gababayo/irishPlay.git (push)
```

> **`mykim` remote URL에 `{배포계정}@`를 포함하는 이유:**  
> Windows 자격증명 관리자가 다른 계정(백업계정)의 토큰을 사용하는 것을 방지한다.  
> URL에 계정명이 있으면 push 시 해당 계정의 자격증명을 별도로 묻는다.

## 2-1단계 — Remote 설정 오류 수정 (잘못 설정했을 때)

`git remote -v` 결과가 아래처럼 뒤바뀐 경우:
```
# ❌ 잘못된 상태 — origin이 배포계정을 가리킴
origin   https://github.com/mykim711231/irishPlay.git
gababayo https://github.com/gababayo/irishPlay.git
```

아래 명령으로 한 번에 교정한다:
```powershell
git remote rename origin mykim
git remote rename gababayo origin

# URL에 계정명 추가 (push 인증 문제 방지)
git remote set-url mykim https://{배포계정}@github.com/{배포계정}/{프로젝트명}.git

# 업스트림 초기화
git branch --unset-upstream

git remote -v  # 결과 확인
```

### `app/src/main.tsx`

```tsx
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import { HashRouter } from 'react-router-dom';
```

> HashRouter는 `/#/path` 형태로 동작해 새로고침·북마크에서도 404가 나지 않는다.

### `.github/workflows/deploy.yml`

이 파일은 수정 없이 그대로 사용한다.

```yaml
name: Deploy PWA to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: app
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
          cache-dependency-path: app/package-lock.json

      - name: Install dependencies
        run: npm ci

      - name: Build
        run: npm run build

      - name: SPA 404 fallback 복사
        run: cp dist/index.html dist/404.html

      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: app/dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

## 8단계 — GitHub Pages 활성화 (최초 1회)

> 예: `https://github.com/mykim711231/irishPlay/settings/pages`

1. `https://github.com/{배포계정}/{프로젝트명}/settings/pages` 접속
2. Build and deployment → Source: **GitHub Actions** 선택 ← 반드시 이 옵션
3. 저장

> "Deploy from a branch"로 되어있으면 Actions가 실행돼도 배포가 안 된다.

### Actions 권한 확인 (안 되면 추가 설정)

1. `https://github.com/{배포계정}/{프로젝트명}/settings/actions` 접속
2. Actions permissions → **Allow all actions** 선택
3. Workflow permissions → **Read and write permissions** 선택
4. 저장

## 9단계 — 배포 확인

- Actions 상태: `https://github.com/{배포계정}/{프로젝트명}/actions`
  - 예: `https://github.com/mykim711231/irishPlay/actions`
- 배포 URL: `https://{배포계정}.github.io/{프로젝트명}/`
  - 예: `https://mykim711231.github.io/irishPlay/`

Actions 설정 후 수동 재실행이 필요하면:
```powershell
# 빈 커밋으로 Actions 재트리거
git commit --allow-empty -m "chore: trigger deploy"
git push mykim main
```

## 문제 해결

| 증상 | 원인 | 해결 |
|------|------|------|
| `Permission denied to {백업계정}` | remote 계정 뒤바뀜 | `git remote -v` 확인 후 2-1단계 교정 절차 실행 |
| `'mykim' does not appear to be a git repository` | mykim remote 없음 | `git remote add mykim https://{배포계정}@github.com/{배포계정}/{프로젝트명}.git` |
| push 시 비밀번호 오류 | Windows 자격증명이 다른 계정 사용 | remote URL에 `{배포계정}@` 포함시키기 |
| `git push` 인증 실패 | PAT 없음 | `https://github.com/settings/tokens` 에서 `repo` 권한 토큰 발급 |
| Actions 빌드 실패 | `package-lock.json` 없음 | `app/`에서 `npm install` 후 커밋 |
| Actions가 실행은 되는데 배포 안 됨 | Pages Source 설정 오류 | Settings → Pages → Source를 **GitHub Actions**로 변경 |
| 배포 후 흰 화면 | `base` 경로 불일치 | `vite.config.ts`의 `/{프로젝트명}/`이 저장소 이름과 대소문자까지 일치하는지 확인 |
| 새로고침 시 404 | SPA 라우팅 문제 | `HashRouter` 사용 확인, `deploy.yml`의 `404.html` 복사 확인 |
| TypeScript 오류 (`ExtendableEvent` 등) | tsconfig lib 누락 | `tsconfig.app.json`에 `"WebWorker"` 추가, `tsconfig.node.json`에 `"skipLibCheck": true` 추가 |
| GitHub Pages 설정 안 보임 | 저장소가 Private | 저장소 Settings → Danger Zone → Make public |
| PWA 설치 안 됨 | HTTPS 필요 | 로컬(`http://`)에서는 불가 — 배포 URL에서만 설치 가능 |
